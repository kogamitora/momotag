# MomoTag

[中文](README.md) · [日本語](README_JA.md) · [English](README_EN.md)

MomoTag は、同人CDやデジタルアルバムなどの音楽ファイルを整理するデスクトップアプリです。アルバムフォルダを選択し、曲目リストとカバー画像を指定すると、アルバム名、アーティスト、年、曲名、曲番号、カバー画像をまとめて書き込めます。

画面は中国語、日本語、英語に対応しています。初期言語はシステムの言語に合わせて自動的に選択されます。日本語のシステムでは日本語、中国語のシステムでは中国語、それ以外のシステムでは英語が選択されます。アプリ内で手動で切り替えることもできます。

## 機能

- アルバムフォルダ内の音声ファイルをスキャンし、ファイル名順に並べ替えます。
- 番号、曲名、アーティストが混在した曲目リストを解析します。
- アルバム名、アルバムアーティスト、年、曲名、曲番号、曲数、カバー画像を一括で書き込みます。
- 変更後のファイル名、曲名、アーティストを編集できます。ファイル名を変更しても拡張子は保持されます。
- JPG、PNG、WEBP のカバー画像に対応し、ローカル画像または HTTP/HTTPS URL を使用できます。
- `cover.jpg`、`folder.jpg`、`front.jpg` など、フォルダ内の一般的なカバー画像を自動検出します。
- 曲目と音声ファイルの対応が未解決の場合は、書き込みを開始できません。
- 書き込み前に一時バックアップを作成し、エラーが発生した場合は可能な範囲で変更を元に戻します。
- 書き込み後にアルバムフォルダをアルバム名に変更できます。
- 起動時にバックグラウンドで更新を確認できます。手動確認にも対応しており、確認後にダウンロード、インストール、再起動を行います。

## 対応形式

スキャン対象の音声ファイル拡張子：

`mp3`、`flac`、`wav`、`m4a`、`ogg`、`opus`、`aiff`、`aif`、`ape`、`wv`

カバー画像形式：`jpg`、`jpeg`、`png`、`webp`。

## 使い方

1. 音声ファイルが入ったアルバムフォルダを選択します。
2. アルバム名、アルバムアーティスト、年を入力します。既存のタグやフォルダ内のカバー画像をもとに候補が自動入力される場合があります。
3. ローカル画像を選択するか、HTTP/HTTPS の画像 URL を貼り付けます。
4. 曲目リストを貼り付け、解析結果とファイルの対応を確認します。
5. 必要に応じてファイル名、曲名、アーティストを編集し、対象外のファイルを除外します。
6. 対応付けが完了していることを確認してから、「タグを書き込む」をクリックします。

この操作はローカルの音声ファイルを変更します。最初はコピーしたファイルで動作を確認してください。別のアプリがファイルを使用中の場合、フォルダ名の変更だけがスキップされ、その結果が表示されます。完了したタグの変更は保持されます。

## 開発

必要な環境：

- Windows 10/11（主な検証環境）
- [Bun](https://bun.sh/)
- Rust stable、Cargo、Tauri 2 に必要なシステム依存関係
- Windows では WebView2 と Visual Studio C++ ビルドツール

依存関係をインストールして、開発モードでアプリを起動します。

```powershell
bun install
bun run tauri dev
```

フロントエンドだけを起動する場合：

```powershell
bun run dev
```

主な確認コマンド：

```powershell
bun run build
bun run tauri build --no-bundle
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

`bun run tauri build --no-bundle` はインストーラーを作成せずにアプリをコンパイルします。

## ブランチ運用

- 長期運用する統合ブランチは `main` のみとし、常にリリース可能な状態を保ちます。変更は Pull Request 経由で取り込みます。
- 新機能は最新の `main` から短期の `feature/<名前>` ブランチを作成します。完了後に `main` 宛ての PR を作成し、レビューと CI の成功を確認してからマージします。
- リリース前に `main` から一時的な `release/vX.Y.Z` ブランチを作成します。このブランチではバージョン更新、リリース準備、リリースを妨げる問題の修正だけを行い、新機能は追加しません。
- リリースブランチを `main` にマージし、検証済みの `main` コミットに `vX.Y.Z` タグを作成します。リリース後、一時ブランチを削除します。
- 長期運用の `develop` ブランチは使用しません。`main` へのマージだけではリリースされず、`v*` タグを push したときにリリースワークフローが起動します。

## リリースと自動更新

リリースワークフローは `.github/workflows/release.yml` にあります。`v*` 形式の Git タグを push すると、GitHub Actions が Windows、macOS、Ubuntu 向けにビルドし、Tauri のアップデート用メタデータを含むドラフト版リリースを作成します。詳しいブランチ運用と手順は [RELEASING.md](RELEASING.md) を参照してください。

公開前に [RELEASING.md](RELEASING.md) を確認してください。`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` のバージョンを一致させ、アップデート用の秘密鍵は絶対にコミットしないでください。
